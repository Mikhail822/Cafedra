# База данных системы событий кафедры ДонГУ

Пакет содержит DDL, тестовые данные, 20 демонстрационных запросов и Docker Compose для PostgreSQL 16. БД намеренно готовится отдельно от настольного приложения: приложение следует начинать после успешного запуска и проверки базы.

## Состав

- `docker-compose.yml` — PostgreSQL 16 с постоянным именованным томом.
- `sql/create_tables.sql` — 12 таблиц, ключи, проверки и индексы.
- `sql/insert_data.sql` — тестовые данные и bcrypt-хеши демонстрационных паролей (генерируются `pgcrypto`).
- `sql/queries.sql` — 20 запросов и запрос выбора активного расписания.
- `sql/verify_database.sql` — проверка количества таблиц и данных, bcrypt-хеша, FK и ключевых ограничений.
- `Проверка_модели.md` — результаты сверки ERwin и ТЗ, включая обоснование 3НФ.

## Запуск после установки Docker Desktop

1. Скопировать `.env.example` в `.env` и задать локальный пароль в `DB_PASSWORD`.
2. Из каталога `DepartmentEvents` выполнить `docker compose up -d`.
3. Убедиться в состоянии `healthy`: `docker compose ps`.
4. Проверить журналы: `docker compose logs postgres`.
5. Подключиться `psql` или pgAdmin/DBeaver к `localhost`, порту `DB_PORT`, базе `DB_NAME`, пользователем `DB_USER`.
6. Выполнить проверку: `docker compose exec -T postgres psql -U department_user -d department_events < sql/verify_database.sql`.
7. Выполнить запросы из `sql/queries.sql`; в `psql` задать переменные, например `-v category_id=2 -v search_text=кафедр`.

Скрипты в `/docker-entrypoint-initdb.d` выполняются только при первом создании пустого Docker Volume. При повторном запуске контейнера они не выполняются. Не используйте `docker compose down -v`, поскольку эта команда удаляет постоянные данные.

Демонстрационные пароли: `ChangeMe-Admin-2026` для `admin` и `ChangeMe-Editor-2026` для `editor.ivanova`. После первоначальной проверки замените их. Самостоятельной регистрации в приложении нет: администратор создаёт учётные записи в разделе «Пользователи», назначает роль и при необходимости блокирует доступ.

## Данные медиаматериалов

Посев создаёт 25 строк Media с относительными путями `media/images/demo_XX.jpg` и `media/videos/demo_XX.mp4`. В пакете уже есть синтетические файлы, которые позволяют проверить пути и чтение изображений/видео; PostgreSQL хранит метаданные и относительные пути, а сами файлы находятся в папке `media/`. Перед реальной демонстрацией замените тестовые паттерны на разрешённые фотографии и видеоролики кафедры.

## Состояние базы

PostgreSQL 16 запущен в Docker Compose; контейнер проверен как healthy, SQL-инициализация прошла без ошибок, все 20 запросов выполнены. Проверочный SQL подтвердил число таблиц, тестовые объёмы, bcrypt-хеш, внешние ключи и ключевые ограничения. Перезапуск контейнера сохранил строки в именованном томе. Все 25 путей Media существуют, а `ffprobe` прочитал тестовые JPG и MP4. База готова к этапу настольного приложения. Скрипты init выполняются только при первом создании пустого Docker Volume.

## Настольное приложение

Нужен Python 3.11 или 3.12 для Windows. Установите его с включённым Python Launcher, запустите Docker Desktop, затем откройте `run.bat` или настройте этот интерпретатор в PyCharm и запустите `main.py`. При первом запуске `run.bat` создаст `.venv` и установит PySide6, SQLAlchemy, psycopg, bcrypt, Pillow и python-dotenv. Вход администратора: `admin` / `ChangeMe-Admin-2026`; вход редактора: `editor.ivanova` / `ChangeMe-Editor-2026`.

В окне входа есть «Открыть демонстрацию без входа». Посетитель не получает доступ к управлению: он выбирает экран и монитор, после чего видит заставку ожидания, ближайшее расписание и актуальную информацию. Демонстрация автоматически запускает текущий активный плейлист и возвращается к заставке после его расписания. Для запуска показов по расписанию оставьте окно демонстрации открытым.

Администратор создаёт аккаунты сотрудников и выдаёт им логины и пароли отдельно. Редактор может готовить собственные медиаматериалы, объявления и плейлисты, но новые и изменённые материалы сохраняются неактивными. Редактирование состава плейлиста тоже снимает его с показа. Администратор проверяет материал и включает поле «Активно», чтобы разрешить показ. Редактор не может менять существующие мероприятия, так как они могут уже входить в утверждённое расписание.

В этой среде Python Launcher есть, но версия Python не установлена. Ранее проверялись подключение к PostgreSQL, вход и создание окон в контейнере Python 3.12. Для запуска и проверки аппаратного воспроизведения видео на Windows сначала установите Python 3.11/3.12.

Приложение включает административное создание учётных записей, ролевой доступ, CRUD-разделы, загрузку медиафайлов с копированием в проект, просмотр фото/видео, управление составом и порядком плейлистов, расписание, статистику, полноэкранный показ с заставкой ожидания и резервное копирование через Docker `pg_dump`. Все изменения выполняются через SQLAlchemy и сохраняются в PostgreSQL.

Подробные результаты проверки базы и приложения: `Проверка_реализации.md`.
