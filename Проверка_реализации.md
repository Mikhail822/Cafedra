# Проверка проекта

## База данных

- Docker Desktop Engine запущен; сервис `department_events_db` показывает `healthy`.
- PostgreSQL 16 выполнил `create_tables.sql` и `insert_data.sql` без ошибок.
- Созданы 12 таблиц и 17 внешних ключей. Проверены рекомендуемые объёмы данных из ТЗ.
- Выполнены все 20 запросов из `sql/queries.sql`.
- `sql/verify_database.sql` проверил количество строк, bcrypt-хеш администратора, внешний ключ организатора, уникальность позиции элемента плейлиста и правило одного объекта контента.
- После перезапуска Compose контейнер остался healthy; 25 медиастрок и 30 элементов плейлистов сохранились в именованном Docker Volume.
- Часовой пояс PostgreSQL — `Europe/Simferopol`.
- Все 25 путей Media разрешаются в файлы. FFprobe декодировал каждый JPG и MP4.

## Настольное приложение

Проверено в изолированном контейнере Python 3.12 с PySide6, SQLAlchemy, psycopg и bcrypt:

- компиляция всех модулей;
- подключение к работающему PostgreSQL;
- вход администратора и редактора;
- регистрация редактора и выдача роли editor;
- создание главного окна обеих ролей; у редактора отсутствуют разделы пользователей и настроек;
- создание форм редактирования для всех 12 моделей;
- загрузка окна состава плейлиста;
- чтение изображения через предпросмотр;
- загрузка элементов активного расписания в полноэкранный показ.

В контейнере Qt Multimedia не имел доступного аудио- и видеобэкенда, поэтому сам вывод видео проверен декодированием файлов FFprobe, а не воспроизведением в PySide6. Для финальной проверки воспроизведения требуется запуск Windows-версии приложения с установленным Python и Qt Multimedia.

## Требование к среде Windows

На компьютере найден `py.exe`, но нет установленной версии Python. Приложение и его зависимости запускались только в тестовом контейнере. Для запуска `run.bat` нужно установить Python 3.11 или 3.12 с Python Launcher. После этого отдельно проверьте окно и воспроизведение MP4 на Windows/телевизоре.
